# Predictive Maintenance System

## Project Overview

The Predictive Maintenance System is an Industrial Internet of Things (IIoT) backend platform designed to monitor industrial machines, collect real-time sensor data, predict machine health using Machine Learning, and generate maintenance recommendations before failures occur.

The system follows a modular architecture consisting of Digital Twin simulation, MQTT communication, MySQL database management, TensorFlow-based prediction, and REST APIs developed using FastAPI.

The primary objective of the project is to demonstrate how AI and IoT technologies can be integrated to build an intelligent predictive maintenance solution suitable for modern manufacturing environments.

---

# Problem Statement

Industrial machines operate continuously and are subjected to wear, environmental conditions, and operational stress. Traditional maintenance strategies are either:

- Reactive Maintenance (repair after failure)
- Preventive Maintenance (scheduled maintenance regardless of condition)

Both methods increase operational cost and machine downtime.

Predictive Maintenance addresses this issue by continuously monitoring machine health and predicting failures before they occur.

---

# Project Objectives

The project aims to:

- Simulate industrial machines using Digital Twins.
- Stream real-time sensor data through MQTT.
- Store sensor history in MySQL.
- Predict machine health using TensorFlow.
- Estimate Remaining Useful Life (RUL).
- Calculate failure probability.
- Generate maintenance alerts automatically.
- Provide REST APIs for future dashboard and mobile integrations.

# System Components

The Predictive Maintenance System consists of the following major modules.

## 1. Digital Twin Simulator

The Digital Twin acts as a virtual representation of an industrial machine.

Each simulated machine continuously generates realistic sensor readings based on predefined operating conditions.

Current simulated machines include:

- Gearbox
- Pump
- Compressor
- Motor
- Conveyor

Each machine produces sensor readings such as:

- Temperature
- RPM
- Torque
- Vibration
- Current
- Oil Level
- Operating Hours
- Operating Load
- Machine Age
- Maintenance Count
- Fault Type

---

## 2. MQTT Communication

Communication between simulated machines and the backend is handled using MQTT.

Architecture:

Digital Twin

↓

Publisher

↓

Mosquitto MQTT Broker

↓

Subscriber

↓

Database

The publisher continuously publishes JSON sensor payloads.

The subscriber receives these payloads and stores them into the MySQL database.

MQTT Topic:

```
machines/sensors
```

---

## 3. MySQL Database

The backend stores all operational data inside MySQL.

Current database tables:

### machines

Stores machine information.

### sensor_data

Stores every sensor reading generated by the Digital Twin.

### predictions

Stores all AI-generated prediction results.

### alerts

Stores maintenance alerts generated based on prediction thresholds.

Relationships:

```
Machines

│

├── Sensor Data

├── Predictions

└── Alerts
```

---

## 4. Machine Learning Module

The intelligence of the system is provided by a TensorFlow LSTM model.

The model predicts machine health using the latest twenty sensor readings.

### Input Features

- Machine Type
- Operating Hours
- Machine Age
- Ambient Temperature
- Operating Load
- Temperature
- RPM
- Torque
- Vibration
- Current
- Oil Level
- Maintenance Count
- Fault Type

Before prediction, the data undergoes:

- Label Encoding
- Feature Scaling
- Tensor Conversion

The processed sequence is then passed to the TensorFlow model.

---

# Prediction Output

The prediction engine generates four outputs.

## Health Score

Represents overall machine condition.

Range:

```
0 - 100
```

Higher values indicate healthier machines.

---

## Failure Probability

Calculated using

```
Failure Probability = 100 - Health Score
```

---

## Remaining Useful Life (RUL)

Current implementation estimates

```
RUL = Health Score × 2
```

Future versions may replace this heuristic with a dedicated RUL model.

---

## Maintenance Recommendation

Recommendations are generated using health score thresholds.

| Health Score | Recommendation |
|--------------|----------------|
| 90 - 100 | Machine Healthy |
| 70 - 89 | Monitor Machine |
| 50 - 69 | Schedule Inspection |
| 30 - 49 | Maintenance Required |
| 0 - 29 | Immediate Shutdown Recommended |

---

# Alert Generation

Whenever a prediction is generated, the backend evaluates the machine's health score.

Depending on the threshold crossed, alerts are automatically created.

Alert levels:

- Low
- Medium
- High
- Critical

Each alert contains:

- Machine ID
- Severity
- Alert Message
- Timestamp
- Acknowledgement Status

# Configuration

The project uses two environment files.

## .env.local

Used by:

- MQTT Publisher
- MQTT Subscriber

Connects to:

```
localhost
```

---

## .env.docker

Used by:

- FastAPI Backend

Connects to Docker services:

```
mysql

mosquitto
```

This separation avoids networking conflicts between Docker containers and local execution.
